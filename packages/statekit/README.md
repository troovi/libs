# @companix/statekit

Минималистичный движок состояния экрана для React. Экран не держит рабочее состояние в `useState`: он один раз
создаёт движок — карту ячеек и производных — и отдаёт его потомкам контекстом. Потомки подписываются на нужную им часть
и пишут свои изменения, поэтому правка перерисовывает только тех, кто читает изменённое, а не весь экран.

```tsx
// движок экрана: ячейки по частям состояния и производная
const createProposalWindow = (draft: KpDraft) => {
  const points = createState(draft.points)
  const rates = createState(draft.rates)
  const conditions = createState(draft.conditions)
  const openId = createState(draft.points[0].pointId)

  const calc = createDerived([points, rates], ([points, rates]) => calcOf(points, rates))

  return { points, rates, conditions, openId, calc }
}

// область с неизменным значением — `createStaticScope` из `@companix/uikit` или свой контекст
const [ProposalWindowScope, useProposalWindow] =
  createStaticScope<ReturnType<typeof createProposalWindow>>('ProposalWindow')

// экран: движок создаётся один раз, на данные экран не подписан
export const ProposalWindow = ({ draft }: { draft: KpDraft }) => {
  const model = useConst(() => createProposalWindow(draft))

  return (
    <ProposalWindowScope value={model}>
      <PointStrip />
    </ProposalWindowScope>
  )
}

// лист: перерисовка — только когда меняется цена этого пункта
const PointPrice = ({ pointId }: { pointId: string }) => {
  const { calc } = useProposalWindow()

  const price = useWatch(calc, (kp) => kp.byId[pointId].price)

  return <span>{price} ₽</span>
}
```

## Почему statekit

- **Экран не перерисовывается от правок.** Состояние живёт в ячейках вне React, экран держит только движок —
  значение контекста не меняется за его жизнь.
- **Подписка на часть.** `useWatch` выбирает из ячейки нужное селектором и перерисовывает компонент, только когда
  выбранное изменилось.
- **Запись будит только своих.** Правка одной ячейки не трогает подписчиков других — ни селекторов, ни перерисовок.
- **Производное — тоже ячейка.** `createDerived` считает один раз на всех читателей, пересчитывается, когда меняются
  источники, и сам служит источником.
- **Без лишнего.** Полторы сотни строк кода, ни одной зависимости, кроме React; привязка к React —
  `useSyncExternalStore`.

## Установка

```sh
npm i @companix/statekit
```

Нужен React 18.

## API

| Что                                    | Для чего                                                                                            |
| -------------------------------------- | --------------------------------------------------------------------------------------------------- |
| `createState(initial)`                 | ячейка: `get()`, `set(value)`, `update(change)`, `subscribe(listener)`; та же ссылка — не изменение |
| `createDerived([...sources], compute)` | производная ячейка: `get()`, `subscribe()`; пересчёт при чтении, если сменился хоть один источник   |
| `batch(run)`                           | несколько записей одним уведомлением; вкладывается                                                  |
| `useWatch(source)`                     | подписка компонента на источник целиком                                                             |
| `useWatch(source, select, { equal })`  | подписка на часть: перерисовка, когда выбранное изменилось по `equal` (по умолчанию `Object.is`)    |
| `shallow`                              | поверхностное равенство объектов и массивов — для селектора, который собирает объект или массив     |
| `useConst(create)`                     | значение, созданное один раз на жизнь компонента, — движок экрана                                   |
| `Source<T>`, `State<T>`                | типы источника и ячейки; `useWatch` и `createDerived` принимают любой `Source`                      |

## Как устроить экран

- **Ячейка — часть состояния, которую правят независимо и целиком:** список пунктов, объект условий, выбор (вкладка,
  открытая запись). Не поле: поля формы держит formkit. Экран из одной ячейки с селекторами — тоже законный случай.
- **Подписка — в листе.** Подписка изолирует только компонент, который её держит: перерисованный компонент
  перерисовывает всех своих детей. Итог блока в шапке читает маленький компонент итога, а не сам блок со строками.
- **Запись в несколько ячеек — действием движка в `batch`:** добавить пункт и сразу открыть его — одна правка для
  подписчиков. Действие объявляется в движке рядом с ячейками, не в компоненте.
- **Движок — один на экран и в контексте с неизменным значением.** Экран создаёт его `useConst` и отдаёт потомкам
  контекстом, значение которого не меняется, — сам контекст никого не перерисовывает. Области statekit не заводит: в
  наших проектах это `createStaticScope` из `@companix/uikit`.
- **Состояние целиком — метод движка:** сохранение и сборка документа читают ячейки `get()` в момент действия, без
  подписки; новая ячейка сразу попадает в этот метод.
- **Форма — редактор своей части.** Начальные значения форма берёт чтением ячейки без подписки, правку пишет в ячейку
  на каждое изменение (`onChange` formkit).
- **Селектор возвращает новый объект или массив — нужен `equal`.** Иначе ссылка новая на каждое уведомление и
  компонент перерисуется; `shallow` сравнивает поля.

## Как это работает

Ячейка хранит значение и множество подписчиков; `set` с новой ссылкой уведомляет их, внутри `batch` — откладывает до
конца пакета, по одному уведомлению на подписчика. Производная ячейка подписывает слушателя на все источники и
пересчитывает результат при чтении, только если сменилось значение хоть одного источника. `useWatch` — это
`useSyncExternalStore` с кешем выбранного: пока значение источника и селектор те же, снимок — прежняя ссылка; новое
выбранное, равное прежнему по `equal`, тоже остаётся прежней ссылкой, и React компонент не перерисовывает.
